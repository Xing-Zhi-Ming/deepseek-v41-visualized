02 / CAUSAL ENCODER-DECODER

Prefill 只跑一半的层

输入很长的 Agent 上下文时，真正贵的是 prefill。CED 让 Decoder 的全局 KV 直接从第 20 层隐藏状态投影出来，而不是让 40 层都重新算一遍。

Decoder 每层只保留自己的投影权重，不再持有独立的全局 K/V 计算路径。

A

输入重，输出轻

Agent 工作流里，输入上下文远多于输出 token。CED 把“读长文”的成本压到约一半，而 decode 仍保留 20 层 Decoder 的生成深度。

B

局部仍然逐层计算

SWA 的局部 KV 仍由每一层自己的隐藏状态生成。省掉的是重复的全局 KV，不是所有注意力。

C

少算，但要少得可控

Decoder SWA 只用最近 128 个 token 做 bounded replay；官方报告称对响应质量的影响可以忽略。

03 / COMPRESSED SPARSE ATTENTION 2

缓存不是每层都存一份

CSA2 从三个维度同时压缩 KV：条目大小、序列长度、层数。 核心动作是把“生成全局 KV”和“重新选 Top-K”拆开，让不同层只做自己必须做的那一部分。

03.2 / HIERARCHICAL SPARSE INDEXER

上下文越长，后面的索引越不该全扫

Decoder 的第一个 Full 层先扫完整上下文，并把高分块放进一个候选池。 后面的 Reindex 层只在池子里重选 Top-512，不再线性扫完整条序列。

FULL LAYER · SCAN ALL 1,000,000 positions scored / query

对因果可见位置打分，选出自己的 Top-512。

02
按块建候选池

每 8 个位置一块，取块内最高分；选最多 2,048 块。

03
Reindex 只在池里选

后续索引器最多评分 16,384 个候选位置。

候选池大小固定，所以后续索引成本随上下文长度增长而有上界；首层仍然需要一次全范围扫描。

05 / SPARSE EXPERTS & CONDITIONAL MEMORY

不是所有参数都要为每个 token 工作

552B 是“总容量”，不是每个 token 的“计算量”。MoE 负责把计算路由到少数专家， Engram 则把可查表的知识从矩阵计算里拿出来，变成条件记忆。

06 / DSPARK

一次草拟 5 个，再决定验几个

DSpark 是 V4.1 的投机解码模块：一个 3 层 drafter 并行给出 5 个草稿位置， Markov head 补 token 间依赖，confidence head 估计每一步的接受概率，调度器再按当前系统负载选验证长度。

07 / POST-TRAINING

算法没变，数据和环境变了

官方报告明确说：后训练没有引入新的算法，仍是 SFT → RL → on-policy distillation。 真正的增量来自大规模任务合成、可验证环境，以及可控的 reasoning effort。

01
任务合成

问题、环境、验证器三元组；自动构造代码与通用 Agent 任务。

02
SFT

用高质量轨迹建立基础行为与工具使用格式。

03
RL

在可验证环境里做大规模异步 rollout，按结果给奖励。

04
OPD

on-policy distillation，把强策略的能力压回目标模型。

近似带来的风险

CSA2 的选择误差与 SWA bounded replay 的近似状态，在未覆盖的极端输入或缓存恢复边界上仍可能造成退化。

版本说明

本文以 2026-09-10 发布的 V4.1-Flash 与其技术报告为准；10-17 的 1017 版本是权重更新，架构口径不变。

09 / ONE-SENTENCE VERSION

V4.1 的核心，是把长上下文拆成两条成本曲线

计算侧，CED 让 Decoder 的 global KV 从 H20 投影，prefill 只跑一半的层； 存储侧，CSA2 让多层共享 KV 与索引，FP4 再把 main KV 压到 4 bit。 两者相乘，才有 1M 上下文下 890 B/token 的 global KV，以及 1/8 的持久化缓存。
